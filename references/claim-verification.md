# 主張と本文根拠の照合

利用枠・権限・画面案内、更新直後の情報、資料間の矛盾など、出典の条件を広げると誤答になる確認に使う。専用の公式資料Skillで取得した本文も再利用できる。主担当・検索を新たに一巡させない。

1. **何を断定するかを分ける。** 対象の利用可否、上限値、リセット、残量表示、確認する操作経路は別の主張。内部では重要主張ごとに対象・条件・本文根拠・未確認を対応させる。利用できることを、無制限・残数表示ありの証拠にしない。
2. **同じ対象の同じ内容を読む。** 製品/利用面、モデル/モード、プラン、組織、地域、適用日を照合する。対象アカウント限定のクレジット購入案内を、全契約のモデル残数表示へ広げない。公式ドメインであることだけでは主張との一致を保証しない。
3. **利用者が示した表記を確かめる。** 「無制限になった」「更新で変わった」等の主張は仮説として扱い、該当原文と対象の表の列・行・脚注を確認する。別モデルの説明だと推測して否定しない。URL等がなく公開資料で特定できない場合は、その前提を未確認とし、確認済み部分だけ答える。結論に必要な不足だけ質問する。
4. **衝突を隠さない。** 料金表、モデル別ヘルプ、リリースノート等で異なる場合、公開/更新日と適用日、契約区分、対象機能、期間限定条件を比べる。古い数値を新しい説明へ混ぜず、一般ページの新しい更新日だけで個別条件を上書きしない。現行の適用を決める根拠がなければ双方を条件付きで示し、矛盾の未解消を伝える。
5. **画面案内も検証する。** 同じ製品・利用面の公式本文か許可された実画面で、メニューの存在とそこで分かる情報を確かめる。別製品で似た名前の画面を代用しない。利用者の画面を見ていなければアカウント固有の表示を断定しない。本文取得で表の一部や動的表示が欠落した時は、可能な範囲で正規の表示を確認し、取得できなければ未確認とする。空欄や検索不一致だけで「存在しない」としない。
6. **回答文を照合して止める。** 各重要主張を、本文が直接支持する事実、根拠を示した推論、未確認に分ける。「可能性が高い」等で根拠のない穴埋めを正当化しない。引用は支える主張の近くに置く。確認先がなくなれば未確認を残し、出典数を増やすだけの検索はしない。

専門Skillの検索先で不足する場合は、利用者の検索範囲指定を守り、当該製品を扱う公式ヘルプ・料金表・発表などへ補う。取得済みの本文は使い回す。Skill本文の例、記憶、古い手順は現行の製品仕様やアカウント状態の直接根拠にしない。
